# `neec_scores.csv` — data dictionary

The canonical corpus of the NEEC Applied framework (v2 structure: 26 criteria
in five domains), one row per scored system. This file describes the columns
as they are; it changes only when the file's format changes.

## The file

- UTF-8, comma-separated, one header row and one row per system (23 systems,
  24 lines, as of Session 28).
- Generated by `neec_scores_csv_builder_v2.py` from the canonical script
  `neec_weighting_robustness_analysis_v2.py`, in the order of that script's
  `SCORES`; never edited by hand. `run_all_checks.py` regenerates it and
  compares it byte for byte.
- **It does not contain the 26 criterion scores.** The criterion-level vector
  of each system is in the canonical script (`SCORES`) and in the summary
  block that ends the system's scoring document (`SCORING_PROTOCOL.md`,
  section 9); `neec_corpus.json`, generated from those sources by
  `build_corpus_file.py`, carries every entry's vector in one file. The domain
  totals here are sums of that vector.

## Columns

| # | Column | Type | Content |
|---|---|---|---|
| 1 | `system` | text | The system's display name, unique in the corpus. The canonical key (the name in `SCORES`) is its prefix; the three state-capitalism entries add a parenthetical, e.g. `State Capitalism / China (Party-State-Directed Market Economy)`. |
| 2 | `criteria_count` | integer | Number of criteria the row is scored on: 26 for every row (the v2 structure). The legacy structure had 25. |
| 3 | `domain1_max` | number | Maximum of Domain 1: 6.0 for every row (six criteria since the C1.2 split). The legacy structure had 5.0. |
| 4 | `domain1_material_security` | number | C1.1 + C1.2a + C1.2b + C1.3 + C1.4 + C1.5; 0 to 6 in steps of 0.5. |
| 5 | `domain2_human_autonomy` | number | C2.1 + ... + C2.5; 0 to 5. |
| 6 | `domain3_system_resilience` | number | C3.1 + ... + C3.5; 0 to 5. |
| 7 | `domain4_ethical_integrity` | number | C4.1 + ... + C4.5; 0 to 5. |
| 8 | `domain5_implementation_viability` | number | C5.1 + ... + C5.5; 0 to 5. |
| 9 | `total_score` | number | Sum of the five domains; 0 to 26. |
| 10 | `total_percent` | text | `total_score` / 26 × 100, rounded to a whole percent, with a `%` sign (e.g. `52%` for 13.5). Whole percents are the protocol's display rule for scores (section 2.4; decision D21, adopted in Session 29). |
| 11 | `failures` | integer | Number of criteria scored exactly 0.0 (structural failures). A 0.5 is never a failure. |
| 12 | `adequacy_tier` | text | Set by `failures` alone, never by the total: 0-2 `Potentially Adequate`; 3-5 `Partially Adequate`; 6 or more `Structurally Inadequate`. |
| 13 | `revision_note` | text | How the row's scores reached their present values (for example, the Step 1c retrofit of the legacy C1.2 and C1.5). Free text, not parsed. Named `corrected_in_v1_1` in earlier versions. |
| 14 | `notes` | text | Context for reading the row. Free text, not parsed. |

## Scores and rules

Each criterion is scored 1.0 (pass), 0.5 (partial) or 0.0 (structural
failure); rounding happens once, at the criterion level, and nothing above it
is weighted or averaged. The scale, the arithmetic and the tiers are defined
in `SCORING_PROTOCOL.md`, section 2; the criteria and their anchors are in
`criteria.json`.
